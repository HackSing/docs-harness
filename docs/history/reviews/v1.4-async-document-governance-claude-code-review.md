# Docs Harness v1.4.0 异步文档治理方案 Claude Code 审查记录

审查对象：`docs/v1.4-async-document-governance-plan.md`  
审查日期：2026-08-03  
审查工具：Claude Code 2.1.220  
审查方式：安全模式、只读输入、无文件编辑权限  
最终结论：通过，可进入实现

## 1. 审查范围

Claude Code 分两部分检查：

1. 产品边界、工作量评分、统一 Job Schema、状态机和简单/复杂宿主路线；
2. 初始化、降级知识准入、增量合并队列、兼容层、安全恢复、真实宿主验收和发布边界。

本次是方案审查，不是代码实现审查。Claude Code 没有修改任何仓库文件。

## 2. 第一轮发现

### 2.1 阻断与重要问题

- 工作量硬升级覆盖评分时，没有同时保留原始分数和覆盖原因；
- Job 有 `attempt`，但没有最大尝试次数；
- `critical_followup` 缺少强制父任务追溯和不可修改父任务的 Schema 约束；
- 部分支持后台、但不支持目标型任务的宿主缺少降级路线；
- `waiting_for_bootstrap_merge` 缺少明确进入和退出条件；
- 用户同意或拒绝知识更新的回执缺少有效生命周期；
- `context_quality=degraded` 与必要证据失败关闭的边界不够确定；
- 初始化结束后，增量 Job 复用旧基线可能造成脏写或丢更新；
- `critical_finding` 与自动重试关系不清，可能重复生成严重事件；
- 缺少 Runtime 归档策略、失败超时提示和兼容命令移除条件；
- 宿主无法提供用户响应时间时，不能声称已经证明“用户界面零等待”。

### 2.2 非阻断建议

- 评估输出增加扫描文件数量；
- `known_limits` 使用受控代码而不是只依赖自由文本；
- 明确 `waiting_for_dependency` 的使用来源；
- CLI `--help` 同步展示兼容命令的替代入口。

## 3. 方案处理结果

| 审查意见 | 处理结果 |
|---|---|
| 评分覆盖不可审计 | 增加 `raw_score`、`score_route`、`route_override_reason` 和 `scan_file_count` |
| 重试可能无限循环 | 增加 `max_attempts=3` 和达到上限后的终态规则 |
| 父任务保护只有文字约束 | 增加 `may_mutate_parent=false`，`critical_followup` 强制绑定父任务和父 Job |
| Job 状态不闭合 | 增加完整允许转换表、`completed_with_finding` 和依赖退出条件 |
| 部分宿主能力不明确 | 区分完全不支持、只支持直接后台、支持目标但不支持并行和完整支持 |
| 拒绝后可能反复询问 | 回执绑定审查与文档盘点指纹；指纹未变时不重复询问 |
| 降级知识与必要证据冲突 | 明确知识背景缺失只降级，业务结果、安全和交付层证据缺失仍失败关闭 |
| 增量 Job 使用旧基线 | 离开合并队列前强制废弃旧基线，按当前工作区重新计算，禁止重放旧文本补丁 |
| 严重发现可能自动重试 | 使用 `completed_with_finding` 终态，禁止自动重试并幂等创建跟进项 |
| 兼容命令移除依据不足 | v1.4 不承诺自动移除；未来移除需要迁移命令、测试、弃用说明和 ADR |
| Runtime 可能无限增长 | 默认保留；提供显式 `prune --dry-run` 与 `--apply`，高风险 Job 不进入候选 |
| 后台失败没有提示边界 | 增加 `stale_after` 和项目黄色提醒；不虚构 Harness 自身推送能力 |
| 用户零等待证据过强 | 有响应时间才证明界面无等待；否则只证明后台不阻塞响应生成 |
| 自由文本限制不可比较 | 增加 `known_limit_codes` 受控枚举和独立说明字段 |
| 依赖状态来源不明确 | 增加 `dependency_job_ids`，只允许分阶段工作包和显式 Job 依赖使用 |
| 弃用提示不易发现 | 要求响应字段和 CLI `--help` 同时展示替代命令 |

## 4. 修订版复核

Claude Code 对修订后的第 1–12 节复核结论：

> 无 P0/P1 阻断问题。评分、重试、父任务保护、状态转换、部分宿主、拒绝回执、上下文质量和增量新基线均已闭环，整体可以进入实现阶段。

Claude Code 对修订后的第 13–23 节复核结论：

> 无 P0/P1 阻断问题。严重发现、兼容层、Runtime 保留、重试排除、失败提醒、宿主验收和用户无等待证据边界已经自洽。

复核提出的两个 P2 建议也已纳入最终方案：

- 明确 `waiting_for_dependency` 只来自显式 Job 依赖或分阶段工作包；
- CLI `--help` 同步显示兼容命令的替代入口。

## 5. 最终结论与边界

最终审查结论：方案可以作为一个 v1.4.0 版本进入实现，不需要拆成两个独立版本。

仍需在实现阶段取得的证据：

- 统一后台 Job 控制器的自动化测试；
- 简单和复杂路线的真实子智能体宿主验收；
- 部分支持和完全不支持后台宿主的降级验收；
- 临时 Git、fresh clone 和交付状态分层证据；
- 宿主能够提供时的用户响应时间证据。

本审查通过只代表方案闭环，不代表 v1.4.0 代码已经实现或交付。
