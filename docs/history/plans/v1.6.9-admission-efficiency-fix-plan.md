# v1.6.9 准入效率修复方案：把 harness 自身开销压到任务总时长 1/4 以内

## 背景与目标

ZBuddy 质量账本记录 `dh-20260806T173420-72df04e033`（2026-08-06）：PPT 链路收敛任务代码+测试一次通过，约占总时长 1/3；**harness 准入修复与补证据约占 2/3**，run/verify/context 重准入循环约 6 轮。用户硬指标：**harness 自身耗时 ≤ 任务总时长的 1/4**。

账本暴露的 5 个返工点，根因全部在 harness 自身（v1.6.8 源码未覆盖）：

| # | 账本现象 | 根因（代码定位） |
|---|---------|----------------|
| 1 | `--scope` 误传 JSON 数组字符串被接受，污染 `allowed_scope`，引发 write_scope_violation / plan_scope_mismatch 死循环 | `validate_scope`（scripts/harness.py:2547）的描述性检查放行含 `/` 的 `'["a","b"]'`；`looks_like_inline_input`（:461）只用于文件参数，未用于 scope |
| 2 | 重准入只修复 `allowed_scope`，漏改同样被污染的 `read_scope` | `merge_recompile_facts`（:4818）逐键继承任务包旧值，无三字段一致性校验；blocked 响应不展示当前 scope 实际值 |
| 3 | Git Bash `/tmp` 路径 Windows Python 读不到，facts 丢失后拿空 facts 重编译 | `load_input_file`（:471）已对缺失文件硬失败（:486），但错误提示未指出 Windows 上 POSIX 绝对路径不可解析、应改用工作区相对路径 |
| 4 | 重新提交方案缺少新版 `plan_fields` 必填字段，多走一轮 needs_plan | needs_plan 响应只列缺失字段；`next_step_payload`（:967）不携带当前 `plan_fields` 合同 |
| 5 | verify 要求的证据类型事先不知，补证据返工 | `completion_manifest` 只在首次准入响应（:4883）中；`next_step_payload` 每步响应只有 next_action/next_command，无合同快照 |

另有一个账本实测才发现的隐藏时序：`--facts` 只有在 blocked/scope_changed 状态的重准入才生效（:4951-4953），非该状态下传 `--facts` 被**静默忽略**。

## 验收标准

- 账本 5 个失败模式各有对应测试：先失败、修复后通过。
- 同类 planned 多 scope 任务的准入循环从约 6 轮降到 ≤2 轮（一次准入 + 一次 verify）。
- `pytest tests/test_harness.py` 全量通过。
- 版本升至 1.6.9，CHANGELOG、contracts.md、SKILL.md、todo.md 同步更新。

## 实施步骤（先失败测试，后实现）

### 阶段 A：方案登记与失败测试

1. 本方案文档 + `docs/todo.md` 登记（相对链接引用）。
2. `tests/test_harness.py` 先写失败测试：
   - T1：`run --scope '["a.ts", "b.ts"]'` 与 facts 中 scope 字段含 JSON 数组字符串 → 报 `invalid_scope_json`，错误含 suggested_fix；
   - T2：非 blocked 且无 scope_changed 时 `run --task-id ... --facts ...` → 响应含 `facts_ignored` 警示与生效条件说明；
   - T3：blocked 重准入响应（next_step_payload）含 `contract_snapshot`（当前 read/write/allowed scope、plan_fields、completion_manifest 证据类型）；
   - T4：Windows 上 `--facts /tmp/xxx.json` 缺失文件错误含工作区相对路径提示（按平台条件断言 suggested_fix 存在即可）；
   - T5：重准入 facts 只覆盖一个 scope 字段时，响应 `contract_snapshot` 可见被继承的其余字段（配合 T3 验证可见性）。

### 阶段 B：输入防呆（堵源头）

3. `validate_scope`（scripts/harness.py:2547）：逐项先用 `looks_like_inline_input` 判定，形似 JSON（`[`/`{` 包裹）即抛 `HarnessError(code="invalid_scope_json")`，带 `actual_vs_expected` 与 `suggested_fix`（"--scope 是可重复单值参数，一次只传一个路径；facts 中 scope 字段必须是字符串数组而非 JSON 字符串"）。CLI `--scope` 与 facts 的 read/write/allowed_scope 均经此函数，一处修复全覆盖。
4. `load_input_file`（:471-497）：文件不存在报错时，若 `path_value` 以 `/` 开头且 `sys.platform == "win32"`，附加 `suggested_fix`："Git Bash 的 /tmp 等 POSIX 路径对 Windows Python 不可解析，请使用工作区相对路径"。
5. run 处理器（:4950 附近）：`facts` 非空但未触发重编译（非 blocked 且无 scope_changed）且非 plan/authorization 流程时，在响应中加入 `facts_ignored: true` 与 `facts_effective_condition`（"--facts 仅在 blocked 或 scope_changed 重准入时生效"），消除静默忽略。

### 阶段 C：每步响应自描述（减少轮次）

6. `next_step_payload`（:967-1036）：返回值统一附加 `contract_snapshot`：
   - `read_scope` / `write_scope` / `allowed_scope` 当前实际值（让污染可见，修复账本返工点 2）；
   - `plan_fields`（needs_plan 时另含 `missing_plan_fields`，修复返工点 4）；
   - `completion_manifest.evidence_types`（verify 前可一次性备齐证据，修复返工点 5）。
   字段体保持小字典，不含任务正文，不违反有界遥测合同。
7. 检查 `next_step_payload` 全部调用点（run/verify/progress/context），确认新字段在所有 blocked/needs_plan/provide_evidence 路径均出现。

### 阶段 D：指引层

8. `managed_agent_block`（harness.py:9610）增补 4 条简明操作规则：`--scope` 单值可重复禁传 JSON；文件参数一律工作区相对路径；重准入 `--facts` 只在 blocked/scope_changed 生效且须同时核对三个 scope 字段（以响应 `contract_snapshot` 为准）；verify 前先按 `completion_manifest` 备齐证据，planned 改方案先 `context --stage plan` 再 `run --plan`。
9. `SKILL.md` 同步记录上述行为变化（invalid_scope_json、facts_ignored、contract_snapshot）。

### 阶段 E：版本与交付

10. `pytest tests/test_harness.py` 全量通过；新增 evals 用例（scope JSON 拒绝 + contract_snapshot 存在）至 `evals/evals.json`。
11. `VERSION` → `1.6.9`，`scripts/harness.py` 的 `VERSION` 同步；`CHANGELOG.md` 记录；`docs/contracts.md` 更新 next_step_payload 响应合同与 `invalid_scope_json` 错误码。
12. 模拟账本场景做端到端验收：planned 路线多 scope 任务，故意触发 scope 错误与证据缺失，确认每步响应自描述、准入轮次 ≤2。
13. ZBuddy 安装与真实回归：单独向用户请示授权后执行（安装副本覆盖 + 同类任务复盘对照账本基线）。

## 安全边界

- 不改动 Gate 判定、授权、证据装订等业务语义；只加输入校验、响应字段与提示文案。
- `contract_snapshot` 只含合同字段，不含任务正文与原始环境信息，遵守有界遥测合同。
- 不自动提交、推送 git；不触碰 ZBuddy 仓库（安装需用户另行授权）。
