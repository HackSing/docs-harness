# v1.7.3 验收循环修复方案：五原因码全治理（write_scope 超集增量扩展 + 证据清单前置）

> 定稿依据：与 Kimi CLI 两轮源码级交叉评审（2026-08-07）。第二轮裁决：修正设计 12 条全部采纳，5 处按评审修正执行，2 处认知更正落入本文档（第 0 节、Q7）。

## 背景与目标

ZBuddy 升级 v1.7.2 后（2026-08-07）真实运行数据显示：verify 平均轮次从 08-06 的 4.14 降到 2.00，最坏从 12 轮降到 7 轮，但仍有 11/18 任务需要 ≥2 轮 verify，一次通过率仅约 28%。非完成原因分布（两日合计）：

| 原因码 | 次数 | 性质 |
|---|---|---|
| `missing_evidence_types` | 18 | 首轮几乎必现，每任务固定多一轮补证往返 |
| `write_scope_violation` | 17 | 循环主因：越界写入触发 exit 4 全量重准入，宿主声明不全时反复循环 |
| `stale_evidence` | 5 | 基线漂移 |
| `missing_receipts` | 4 | 收据缺失 |
| `concurrent_drift_overlap` | 4 | 并发漂移 |

典型样例：`dh-20260807T180410-4a8ee2a4c9` 连续 3 轮 `write_scope_violation` + 3 次 `full_readmission`（每轮重编译合同 + 重冻 plan，harness 耗时 39.5s）；昨日 `dh-20260806T173420-72df04e033` 连续 8 轮越界 + 11 次重准入。

**目标（分级承诺）**：

| 原因码 | 治理等级 |
|---|---|
| `missing_evidence_types` / `missing_receipts` / `action_context_missing` | **控制器可消灭**（清单前置 + 骨架预生成 + 状态位自查） |
| `write_scope_violation`（无授权、非 git_sync） | **可消灭**（verify 内增量扩展） |
| `write_scope_violation`（授权任务 / git_sync） | **一次重准入即过**（readmission_hint 精确载荷，安全边界所致） |
| `stale_evidence` | **零试探，至多一轮**（changes-preview 前置 + 精确载荷；宿主预览后继续写入的时序窗为残留） |
| `concurrent_drift_overlap` | **失败后一次重准入即过**（唯一无确定性承诺的码：重叠为必需写入路径时依赖并发落定） |

不放宽任何 Gate、授权或证据装订语义。

## 0. 认知更正（评审裁决，必须贯彻）

**更正 1：仅扩 `allowed_scope` 的缺陷真实边界。** 初稿曾表述"allowed_scope 只在 read_scope 为空时才并入 write_scope"，有误——L3030-3034 的分支条件是 `mutation_profile == "read_only"`。对 write_scope 非空的写任务（主路径），`allowed_scope` 经 legacy 路径并入 write_scope 且 `validate_scope` 末尾 `dict.fromkeys` 去重（L2649），"碰巧有效"；但该缺陷在三个子场景真实成立：

1. **write_scope 原为空的任务**（allowed_scope 派生自 read_scope，L3064）：仅扩 allowed_scope 会把只读路径拖入 write_scope，语义污染；
2. **git_sync 覆写**（L3060-3063）：`git_sync_scope` 非空时 write_scope 被 git 预检清单无条件覆写，facts 扩展被静默丢弃；
3. **隐式依赖脆弱**：主路径依赖"allowed_scope ≡ write_scope（非空时）+ 去重"两个隐式不变量。

结论：facts 载荷一律显式给 `write_scope`（不给 allowed_scope），由 L3064/L3275 确定性派生 allowed_scope。

**更正 2：concurrent_drift_overlap 的消解机制。** "把重叠路径声明进 concurrent_drift 证据"不解决 overlap——`concurrent` 集合正是由该证据声明构成（L5857-5863），overlap 是声明路径与 scope/read_set 的交集（L5884-5886）。正确消解方式只有两条：收窄 scope 剔除重叠路径，或等并发变更落定后全量重准入刷新 freeze 基线（落定变更进入新基线即不再是 drift）。

## 设计要点

### A. write_scope 严格超集增量扩展（`incrementally_extend_write_scope`）

**接入点**：`verify_task` L7135 块内、L7136 `stable_contract` 计算之后、L7137 auto-attribution 分支之前，作为该块第一分支。互斥性成立：扩展要求 `blocker_codes == {"write_scope_violation"}`，auto-attribution 要求 ⊆ `{unattributed_drift_overlap, new_risk_gate}`，天然互斥。重算归因后手工同步 `changed`/`outside`/`new_gates`/`blocker_codes` 四变量，复用 L7105-7114 样板。

**前置条件（全部满足才启用，任一不满足失败关闭、行为与现版本逐字节一致）**：

- 合同稳定：无 `rule_errors` 且激活规则与冻结规则一致（`stable_contract`）；
- `blocker_codes == {"write_scope_violation"}`：只处理纯越界，与其他任何 blocker 共存一律不启用；
- 执行路线为 `direct` 或 `planned`（`extended` 拒绝：工作包单独冻结 begin 快照，语义不同）；
- **排除 `package["git_operation"] == "git_sync"`**（更正 1-2：git 预检清单才是其权威 scope，走 C 的 readmission_hint 重准入）；
- 以 `merge_recompile_facts(package, {"write_scope": 原write_scope ∪ outside_paths})` 重编译候选包（**只给 write_scope，不给 allowed_scope**；read_scope 原样保留，绝不把只读路径并入 write_scope），除 scope 外的全部稳定字段（显式常量 `STABLE_FIELDS_MINUS_SCOPE`：L6004-6027 清单去掉 `allowed_scope`/`write_scope`，其余含 `read_scope`/`git_scope`/`git_sync_scope`/`mutation_profile`/`plan_fields` 间接项全部保留）逐字段一致，且 `blockers` 为空；
- 候选包 `matched_gates` 不新增；
- `planned` 路线额外要求候选 `plan_fields` 不变；
- 授权继承可行：`authorization_requirements` 为空，或 `authorization_adoption_record` 成功。`authorization_contract_fingerprint` 包含 scope → 需要授权的任务一律继承失败、走 C；
- 扩展次数上限：单任务最多 3 次，计数来源 = 扫 `events.jsonl` 中 `scope_extension_readmission` 事件数（`readmission_count` L1072-1111 同款先例，不新增 state 字段），超限 exit 4 + `scope_extension_limit_exceeded`。

**执行语义**：

1. `build_package` 重编译 → `package_revision + 1`、保留 `created_at`、写入 `recompiled_at`；
2. **硬断言**：candidate `write_scope` 必须覆盖 `原write_scope ∪ outside_paths`，不满足即失败关闭回退全量重准入（防 git_sync 覆写等任何未知覆写路径）；write_scope 原为空的任务给 write_scope 会触发 L3041-3042 提升 `mutation_profile` → 稳定比对自然失败关闭，这是有意设计，不当 bug 修；
3. 证据继承三处：
   - 既有索引内收据：重绑新 fingerprint，照搬 L6067-6077 **全部审计字段**（`origin_package_fingerprint`/`adopted_from_package_fingerprint`/`package_fingerprint = new`/`adoption_reason = "scope_superset_extension"`/`adopted_at`），索引按 source_fingerprint 替换；
   - 本轮 supplied 证据（尚未入索引）：内存 dict 按同款全审计字段重绑；必须在 L7247 `state_lock` 索引写入**之前**完成，使 `index_evidence`（L7274）落索引即为新绑定，后续 L7291-7297 `binding_valid` 重检通过；宿主重复提交同源证据由 source_fingerprint 替换逻辑覆盖，查重（L5945）不会双写；
   - reusable 证据按新指纹重过滤；
   - `binding_target_identity` 不受影响（只依赖 target 路径 L7020/L5775-5779，扩展不改 target）；
4. 计数检查、`archive_and_rewrite_package`、`scope_extension_readmission` 事件（含 `extended_paths`、`prior_package_fingerprint`、`adopted_evidence_ids`、`disposition`）全部放入同一 `state_lock` 临界区（照抄 L6079-6110 结构）；
5. 以扩展后的包重算 `workspace_change_attribution`，同一 verify 调用内继续后续证据评估；
6. 最终响应附加 `scope_extended: true` 与 `extended_paths`。

### B. 证据清单前置（消灭 missing_evidence_types / missing_receipts 首轮必现）

1. **骨架前置**：verify 路径骨架生成（L7351-7366）抽取为 `ensure_evidence_skeletons` 助手，verify 与准入共用；骨架 JSON 增加 `_instructions` 注释字段（write_set 必须与 verify 时刻实际变化集精确对齐，不可虚报未变化路径 + 必填收据说明）。`load_evidence` 不校验未知字段，不破坏既有解析。
2. **`evidence_checklist` 四段**：
   - `required`：`completion_manifest.required_evidence_types`，含 fast_track 的 `test_run`（L3213）；
   - `conditional`：standard 的 `test_result` 预告（激活条件：声明验证命令且存在任务写入，L7325-7329）；
   - `required_receipts`：含 **write_set 条件性标注**（L7334 `and changed`：存在任务写入时必填，无写入时不要求，必须标明以免虚警）；`read_set`/`git_state_snapshot` 为准入时确定的硬要求（L7332/L7336）；
   - `skeletons`：已预生成骨架路径列表。
3. **三处响应携带**：
   - `first_run_payload`（L5031-5066，首次 run 与幂等复用）；
   - 二次 run 的 ready 响应（L5490-5499，**当前完全不含 manifest/checklist，是现版本真实盲区**）；
   - `task status`（L4240-4248），只读查询、零状态变更。

### C. 越界重准入提示（A 不适用时的兜底）

verify 因 `write_scope_violation` 走全量重准入时（授权任务、git_sync、extended、混合 blocker、扩展超限），响应仿照 `new_risk_gate` 的 `readmission_hint`（L7229-7245）：

- `message`：提示按模板一次重准入；
- `facts_template`：**只含 `write_scope = 原write_scope ∪ outside_paths`**（不给 allowed_scope）；
- `example_argv`：`harness_command_argv("run", target, "--task-id", <id>, "--facts", "<facts.json>")`。

### D. stale_evidence：changes-preview + 精确载荷

1. `task` 新增 action `changes-preview`（L11355 choices 增项 + `command_task` L4226 分支，复用 `--task-id`，恒只读无 `--apply`）。裁决理由：不并入 `task status`（status 是零计算摘要合同，全工作区 diff 会使其变质）；不做顶层子命令（CLI 惯例动作挂既有入口，prune `--dry-run`/migrate 缺省预览有先例）。实现用 `workspace_snapshot(target)` + `snapshot_changes(freeze["workspace_snapshot"], ...)` 纯函数计算，**不调** `cached_workspace_snapshot`、不写 compiled、不追加事件，零状态变更。顺带输出 read_set 指纹漂移预览（数据源现成），把 `read_set_drift` 也压到零试探；
2. stale_evidence 硬错误载荷（L7249-7263）附 `actual_changed_paths`（verify 时刻 `changed` 全量）与 `stale_write_paths`（现有 missing_items 逐路径清单提升到顶层）。

### E. concurrent_drift_overlap：双选项 readmission_hint

exit 4 载荷（L7221-7245 块内）加 `readmission_hint`，`facts_template` 按更正 2 给两个选项：

- **选项 1 收窄 scope**：剔除重叠路径后的 `read_scope`/`write_scope`，适用于任务不真正需要这些路径；
- **选项 2 等并发落定后全量重准入**（不带 scope 变更）：重冻 freeze 基线，落定变更进入新基线，drift 自然消解；适用于任务必需写入这些路径。

方案与 CHANGELOG 写明：该码控制器侧只保证"失败后一次重准入即过"，不承诺首轮必过。

### F. action_context_missing：状态位前置

run（三处同 B-3）与 `task status` 响应增加 `pending_context_receipts`：数据源 `package["context_schedule"]["action"]`（L6992-6998 判定所据，准入时已知），给出具体待加载阶段（action/plan/work_package），宿主执行前自查。

## 残留与预期对齐（如实声明）

1. `concurrent_drift_overlap`：环境依赖残留。重叠路径与任务必需写入路径冲突时，只能等并发落定——5 码中唯一控制器无法给确定性承诺的；
2. `stale_evidence`：时序窗残留。预览后到 verify 之间的新写入仍会使 write_set 失准——宿主行为问题，控制器侧已到顶；
3. `write_scope_violation`（授权任务子集）：安全边界残留。授权合同指纹含 scope，扩围必变指纹 → 只能一次重准入即过，有意设计；
4. 非目标码同族残留：`read_set_drift`（changes-preview 顺带覆盖）、`high_risk_drift`、`new_risk_gate` 不在本次目标内，如实标注。

## 验收标准

先写失败测试（命名 `test_v173_*`）：

- T1：direct 任务纯越界，verify 一次调用内扩展并 complete；candidate write_scope 显式扩展断言；事件含 `extended_paths`；响应含 `scope_extended: true`；

- T7：三处响应 `evidence_checklist` 齐全（含 write_set 条件性标注）；verify 失败路径与准入预生成骨架一致（同一助手）；
- T8：extended 路线越界 → 不扩展；
- T9：auto-attribution、new_risk_gate 增量、read_set_drift 路径不回归；
- T10：write_scope 原为空的任务扩展 → 失败关闭回退全量，read 路径不被并入 write_scope；

## 前置验证加固（V1–V6，发布前全部完成，不得带到真实项目再暴露）

原则：本次动机全部来自 ZBuddy 账本真实数据，验证必须回指真实故障而非只靠构造用例；任何一级失败即停止发布。

### V1 回放式复现（真实账本驱动，最高优先级）

以 ZBuddy 质量账本 08-06/08-07 记录的真实任务为蓝本（账本在宿主侧 `<git-dir>/docs-harness/quality-ledger/`，回放前先取回相关条目，至少含 `dh-20260807T180410-4a8ee2a4c9` 与 `dh-20260806T173420-72df04e033` 的原因码序列），为五个原因码各构造最小复现序列（命名 `test_v173_replay_*`），断言新行为而非仅不报错：

- `write_scope_violation`：复现样例「连续 3 轮越界 + 3 次 `full_readmission`」→ 断言无授权 direct/planned 任务一次 verify 内扩展完成，零全量重准入；
- `missing_evidence_types`：复现「首轮必现补证往返」→ 断言按 `evidence_checklist` 一次备齐后 verify 不再因缺证据类型失败；
- `stale_evidence`：复现基线漂移 → 断言 changes-preview 输出与 verify 时刻归因一致，宿主按 `actual_changed_paths` 修正后一次通过；
- `missing_receipts` / `concurrent_drift_overlap`：断言分别落在「清单前置消灭」与「失败后一次重准入即过」的承诺等级内，不多不少。

### V2 交互与失败关闭矩阵（补 T1–T17 盲区）

新增 `test_v173_matrix_*`：

- 扩展成功后重复 verify 幂等（第二次不再触发扩展，无 `already` 之外的新事件）；
- 宿主对同一 source_fingerprint 重复提交证据 → 索引替换不双写，`binding_valid` 复检通过；

## 安全边界

- A 只在纯越界、合同稳定、无新 Gate、无授权约束、非 extended、非 git_sync 时启用，任一前置不满足失败关闭回退现行为；candidate scope 硬断言兜底未知覆写路径；
- 扩展上限 3 次防无界循环；
- 授权任务扩围必然改变授权合同指纹 → 强制全量重准入，不存在授权绕过；
- B/C/D/E/F 只新增响应字段、只读 action 与预生成受管工件，不改判定逻辑；changes-preview 零状态变更；
- 事件 schema 只新增受控原因码与字段，不删改既有字段；遥测口径不变；
- 不自动提交推送 git。
