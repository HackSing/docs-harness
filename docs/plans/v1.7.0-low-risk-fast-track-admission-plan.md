# v1.7.0 低风险任务轻量准入通道方案：按任务风险裁剪流程深度

## 背景与目标

v1.6.9 已把"同类任务准入轮次"从约 6 轮压到 ≤2 轮，但账本基线暴露的成本结构仍显示：**所有任务不分大小走同一条重流程**。对低风险小任务（如单文件文档修订、规则文案微调、单测补充），证据装订与 plan/TODO 前置物的流程开销经常超过任务本身的实现成本。

本方案对应效率审查的三个问题点，根因同一条：准入路径没有任务分级通道。

| # | 现象 | 根因（代码定位） |
|---|------|----------------|
| 1 | 低风险任务也要走完整准入—验收往返 | `compile` 路径（scripts/harness.py:3006-3010）只有 direct/planned/extended 三档路线，direct 路线仍走与普通任务相同的证据要求 |
| 2 | 证据仪式感对小任务是纯开销 | `build_completion_manifest`（:2775）按 `semantic_evidence`（:3080）逐规则累加证据类型，无低风险裁剪入口；verify 按 `required_evidence_types`（:3259）全量校验 |
| 3 | 任何任务都要先建 plan 文档+TODO 登记 | planned 路线一律 `needs_plan`（:3121），无 inline 快速登记通道 |

**目标**：低风险任务 harness 自身开销 ≤ 任务总时长 1/10；高风险任务流程深度完全不变。

## 设计要点

### fast_track 任务分类

- 新增任务事实字段 `fast_track: true`（显式声明，不自动推断，避免 Gate 推断不对称重演）。
- 准入条件（全部满足才生效，任一不满足即静默降级为普通流程并在响应中标注 `fast_track_denied_reason`）：
  1. 推断/声明路线为 `direct`；
  2. 未命中任何 `high_gates`（:3005）与 `SAFETY_FLOOR_GATES`（:5702）；
  3. `write_scope` 全部落在文档/规则/测试路径（复用 `infer_gates_from_paths` 判定，不引入新的路径分类真源）；
  4. 无 `work_packages`（非 extended）。
- fast_track 任务准入响应直接为 `ready_direct`，跳过 `needs_plan`。

### 证据裁剪

- fast_track 任务的 `completion_manifest.required_evidence_types` 收敛为最小集：`test_run`（含测试的任务）+ `code_diff`；语义规则累加的扩展证据类型（:3080）不叠加。
- verify 对 fast_track 任务仅校验最小证据集；裁剪结果必须显式写入响应字段 `evidence_profile: "fast_track"`，禁止静默裁剪。

### plan/TODO 内联通道

- fast_track 任务允许通过 facts 携带 `inline_note`（≤200 字）替代独立 plan 文档；CLI 将其落入任务包 `plan_fields` 合同，不写 `docs/plans/`。
- 非 fast_track 任务的 TODO 写入原则（先建方案文档）完全不变。

### 降级与防滥用

- 运行期 scope_changed、drift 引入 `new_risk_gate`（:5725）或命中 high gate → 任务立即降级为普通流程，`fast_track: false` 写回任务包，降级原因进入响应。
- fast_track 声明不豁免任何 Gate 判定；Gate 推断结果与 fast_track 声明冲突时以 Gate 为准。

## 验收标准

- 先失败测试：
  - T1：合法 fast_track facts → 准入 `ready_direct`，响应含 `evidence_profile: "fast_track"`，`required_evidence_types` 为最小集；
  - T2：fast_track 但 write_scope 命中 high gate → 降级为普通流程，响应含 `fast_track_denied_reason`；
  - T3：fast_track 运行期触发 `new_risk_gate` → 任务包降级，verify 按普通证据集校验；
  - T4：非 fast_track 任务行为逐字节不变（对照 v1.6.9 既有测试全量通过）；
  - T5：fast_track + `inline_note` → 任务包含内联 note，不产生 `docs/plans/` 写入。
- `pytest tests/test_harness.py` 全量通过；evals 增加 fast_track 准入与降级用例。
- 版本升至 1.7.0；VERSION、package.json、SKILL.md frontmatter、harness.py `VERSION` 常量四处一致；CHANGELOG、contracts.md、todo.md 同步。

## 实施步骤

1. 本方案登记 + todo.md 相对链接（本文件即方案文档）。
2. 阶段 A：先写 T1–T5 失败测试。
3. 阶段 B：实现 fast_track 准入判定与降级逻辑（compile 路径 + facts 校验 + 任务包字段）。
4. 阶段 C：实现证据裁剪（`build_completion_manifest` 入口加 `evidence_profile` 参数；verify 按 profile 校验）。
5. 阶段 D：实现 `inline_note` 内联通道；更新 `managed_agent_block` 与 SKILL.md 指引。
6. 阶段 E：全量测试 + evals + 版本与文档同步（四处版本一致性由方案二工具兜底前，手工核对）。

## 安全边界

- 不改动 Gate 判定、授权、证据装订（evidence-receipt/v2）语义；只新增一条按风险裁剪深度的平行通道。
- fast_track 只允许声明制，不做自动推断；任何推断与声明冲突以 Gate 为准。
- 降级是单向的：fast_track → 普通流程，不存在反向升级。
- 不自动提交、推送 git。

## 开放问题

- `inline_note` 是否需要进入知识账本以便事后审计（建议：是，随任务包归档）。
- fast_track 最小证据集中是否保留 `code_diff`（无 diff 类变更如纯配置任务的处理方式）。
