# Docs Harness v1.6.8 可用性缺口修复计划

## 1. 方案状态

- 目标版本：`v1.6.8`
- 当前状态：方案已授权，实施中
- 方案范围：跨平台任务工作流、授权文件模板生成、错误提示 actionable 化、外部完成任务补录机制
- 唯一方案真源：本文档
- 当前源码基线：`v1.6.7` 已提交工作区
- 输入来源：ZBuddy 质量账本 3 条真实任务复盘记录（2026-08-05 至 2026-08-06）

## 2. 背景与问题边界

ZBuddy 质量账本记录了 3 个真实任务，共阻塞约 35 分钟、14 次试错，其中 2 个任务最终绕过 harness 完成。这些记录验证了 v1.6.4 计划的问题诊断，同时暴露了 4 个未被现有计划充分覆盖的可用性缺口：

### 2.1 缺口一：跨平台任务验证无法闭环

**账本证据**：任务 `dh-20260806T104805-d69ef8767e`（testing-acceptance）

在 macOS 上修改 Windows 专属脚本（`.ps1`）时，harness 的验证命令无法在 macOS 执行，导致验证流程无法闭环。用户被迫绕过 harness 验证，在 Windows 环境补验。

**现有计划缺口**：v1.6.4 和 task-admission-efficiency 计划均未涉及"平台感知"和"分层验证"概念。

### 2.2 缺口二：授权文件模板/自动生成缺失

**账本证据**：任务 `dh-20260805T192102-6f3d1ad391`（git-operation）

授权文件 schema 复杂且格式隐晦：git scope 格式为 `.git:refs/remotes/origin/main`，external scope 格式为 `origin` 而非 `git-remote:origin`。用户不看源码 `CONTROLLED_GIT_SCOPE_RE` 正则猜不到正确格式。

**现有计划缺口**：v1.6.4 §9.3 聚焦授权摄取和复用（adoption），未解决"首次创建授权文件"的可用性问题。

### 2.3 缺口三：错误提示不 actionable

**账本证据**：3 条记录共同反映

- 授权范围未覆盖任务包：只说"未覆盖"，不说任务包声明的 scope 是什么、授权文件里写的是什么、缺了哪一项、应该怎么改
- stale_evidence：只说"write_set 包含实际未变化路径"，不指出具体路径和修复方法
- 证据格式要求靠报错发现：`--evidence` 只接受单个 JSON 对象不接受数组、write_set 不能含 git 未跟踪产物路径

**现有计划缺口**：各计划提到 `reason_code` 和 `next_action`，但未强制要求 `suggested_fix` 或 `missing_items` 字段。

### 2.4 缺口四：外部完成任务无补录机制

**账本证据**：任务 `dh-20260805T192102-6f3d1ad391` 和 `dh-20260806T104805-d69ef8767e`

两个任务最终都绕过 harness 直接执行完成。这些"外部完成"的工作无法纳入 harness 的任务账本和质量账本，导致：
- 任务状态永远停留在非终态
- 质量账本缺少完整记录
- 后续无法复用这些任务的经验教训

**现有计划缺口**：现有计划假设任务始终在 harness 内闭环，未考虑"绕过 harness 完成后如何补录"的场景。

## 3. 产品目标

1. 跨平台任务在创建时即被识别，验证阶段自动分层：当前平台可执行的验证正常执行，不可执行的验证生成"待补验"清单。
2. 用户可通过 `harness authorization template` 命令生成符合 schema 的授权文件模板，无需阅读源码。
3. 所有阻断性错误必须携带 `suggested_fix` 字段，包含具体缺失项和修复命令。
4. 外部完成的任务可通过 `harness task adopt` 补录，将外部完成的工作纳入任务账本和质量账本。

## 4. 非目标与不可放松边界

- 不降低跨平台任务的安全 Gate 要求；平台分层只影响验证执行方式，不影响 Gate 编译。
- 授权文件模板生成不等于自动授权；用户仍需显式提交授权文件。
- `suggested_fix` 只是建议，不自动执行；用户仍需显式确认。
- `task adopt` 不伪造证据；只记录"外部完成"的事实和用户提供的外部证据引用。
- 不改变 `runtime_status`、当前 HEAD、远端、fresh clone 分层验收原则。

## 5. 缺口一：跨平台任务工作流

### 5.1 平台检测

在任务准入时检测任务涉及的文件后缀，识别平台专属任务：

```python
PLATFORM_SPECIFIC_EXTENSIONS = {
    ".ps1": "windows",
    ".bat": "windows",
    ".cmd": "windows",
    ".sh": "unix",
    ".bash": "unix",
    ".zsh": "unix",
}
```

当前平台通过 `sys.platform` 检测：
- `win32` → `windows`
- `darwin`/`linux` → `unix`

### 5.2 任务包扩展

task-package/v2 新增字段：

```json
{
  "platform_scope": {
    "detected_platforms": ["windows"],
    "current_platform": "unix",
    "cross_platform": true,
    "verification_layers": [
      {
        "layer": "current_platform",
        "platform": "unix",
        "commands": ["python3 -m pytest tests/test_script.py"],
        "status": "executable"
      },
      {
        "layer": "target_platform",
        "platform": "windows",
        "commands": ["powershell -File scripts/test.ps1"],
        "status": "pending_verification"
      }
    ]
  }
}
```

### 5.3 验证分层

`verify` 命令处理跨平台任务时：

1. 执行 `current_platform` 层的所有验证命令，正常生成证据。
2. 对 `target_platform` 层的验证命令，不执行但生成 `pending_verification` 记录。
3. 完成回执中明确标注：`cross_platform_verification_pending=true`，列出待补验命令。
4. 用户在目标平台执行补验后，可通过 `verify --platform-layer target_platform --evidence <file>` 提交补验证据。

### 5.4 准入提示

跨平台任务在 `run` 响应中增加提示：

```json
{
  "cross_platform_notice": {
    "detected": true,
    "target_platform": "windows",
    "current_platform": "unix",
    "message": "检测到 Windows 专属文件(.ps1)，当前平台(macOS)无法执行完整验证。建议在 Windows 环境补验，或使用 --platform-layer 提交补验证据。",
    "verification_layers": ["current_platform", "target_platform"]
  }
}
```

## 6. 缺口二：授权文件模板生成

### 6.1 新命令

```bash
harness authorization template --target <path> --task-id <task_id> [--output <file>]
```

### 6.2 模板内容

根据任务包的 `allowed_scope`、`write_scope`、`git_scope`、`external_scope` 自动生成：

```json
{
  "schema_version": "docs-harness/authorization/v2",
  "task_id": "dh-20260805T192102-6f3d1ad391",
  "package_fingerprint": "sha256:...",
  "authorized_at": null,
  "authorized_by": null,
  "expires_at": null,
  "authorized_scope": {
    "write_scope": ["smartclaw/build-smartclaw-z-mac-domestic-dmg.sh"],
    "git_scope": [".git:refs/remotes/origin/main"],
    "external_scope": ["origin"]
  },
  "constraints": [],
  "_template_hints": {
    "git_scope_format": ".git:refs/remotes/<remote>/<branch>",
    "external_scope_format": "<remote> (not git-remote:<remote>)",
    "write_scope_format": "project-relative path or glob, must match task package exactly"
  }
}
```

### 6.3 交互式生成

当任务包已存在时，模板自动填充任务包中的 scope 值，用户只需填写 `authorized_by` 和 `expires_at`。

当任务包不存在时，生成空模板并附带格式说明。

## 7. 缺口三：错误提示 actionable 化

### 7.1 强制规范

所有阻断性 `HarnessError` 必须携带以下字段之一：

- `suggested_fix`：具体修复命令或操作步骤
- `missing_items`：缺失项清单（适用于 scope 不匹配、证据缺失等场景）
- `actual_vs_expected`：实际值与期望值对比（适用于指纹不匹配、版本不一致等场景）

### 7.2 重点改造场景

#### 7.2.1 授权范围未覆盖

当前错误：
```json
{"code": "authorization_scope_uncovered", "message": "授权范围未覆盖任务包"}
```

改造后：
```json
{
  "code": "authorization_scope_uncovered",
  "message": "授权范围未覆盖任务包",
  "missing_items": [
    {
      "scope_type": "git_scope",
      "required": ".git:refs/remotes/origin/main",
      "authorized": null,
      "hint": "git_scope 格式为 .git:refs/remotes/<remote>/<branch>"
    },
    {
      "scope_type": "external_scope",
      "required": "origin",
      "authorized": null,
      "hint": "external_scope 格式为 <remote>，不是 git-remote:<remote>"
    }
  ],
  "suggested_fix": "harness authorization template --target . --task-id dh-xxx --output auth.json && edit auth.json && harness run --authorization auth.json"
}
```

#### 7.2.2 stale_evidence

当前错误：
```json
{"code": "stale_evidence", "message": "write_set 包含实际未变化路径"}
```

改造后：
```json
{
  "code": "stale_evidence",
  "message": "write_set 包含实际未变化路径",
  "missing_items": [
    {
      "path": "smartclaw/dist/app.dmg",
      "reason": "git_untracked_or_unchanged",
      "hint": "write_set 只写 git 可跟踪的源码路径，构建产物路径不要写入"
    }
  ],
  "suggested_fix": "git status --short && git diff --name-only 核对实际变更，从 write_set 中移除未变化路径"
}
```

#### 7.2.3 证据格式错误

当前错误：
```json
{"code": "invalid_evidence_format", "message": "证据格式无效"}
```

改造后：
```json
{
  "code": "invalid_evidence_format",
  "message": "证据格式无效",
  "actual_vs_expected": {
    "actual": "JSON array",
    "expected": "single JSON object per --evidence parameter"
  },
  "suggested_fix": "每个 --evidence 参数对应一个 JSON 对象文件；如需提交多个证据，使用多个 --evidence 参数"
}
```

## 8. 缺口四：外部完成任务补录机制

### 8.1 新命令

```bash
harness task adopt --target <path> --task-id <task_id> \
  --outcome <summary> \
  [--external-evidence <file>] \
  [--bypass-reason <reason>]
```

### 8.2 补录流程

1. 校验任务存在且处于非终态。
2. 记录 `adopted_externally=true`、`bypass_reason`、用户提供的 outcome summary。
3. 如提供 `--external-evidence`，摄取到受管 artifact store，标记为 `external_adoption` 类型。
4. 任务状态转为 `complete`，`verification_status` 标记为 `adopted_external`。
5. 生成 adoption 事件，包含：任务 ID、原始 package fingerprint、adoption 时间、操作者、bypass reason。
6. 提示用户可将本次经验添加到质量账本：`harness ledger add --task-id <task_id> --review <file>`。

### 8.3 补录记录结构

```json
{
  "schema_version": "docs-harness/task-adoption/v1",
  "task_id": "dh-20260805T192102-6f3d1ad391",
  "adopted_at": "2026-08-06T03:36:36Z",
  "adopted_by": "user",
  "original_package_fingerprint": "sha256:...",
  "bypass_reason": "authorization_flow_too_complex",
  "outcome_summary": "代码提交并推送到 GitHub 和 codeup 完成",
  "external_evidence_refs": ["sha256:..."],
  "verification_status": "adopted_external",
  "quality_ledger_prompted": true
}
```

### 8.4 与质量账本联动

`task adopt` 完成后，输出提示：

```json
{
  "status": "adopted",
  "task_id": "dh-xxx",
  "next_action": "ledger_add",
  "message": "任务已补录。建议将本次经验添加到质量账本：harness ledger add --task-id dh-xxx --review <review-file>"
}
```

## 11. 必需回归矩阵

### 11.1 错误提示 actionable 化

1. 授权范围未覆盖：错误包含 `missing_items` 和 `suggested_fix`。
2. stale_evidence：错误包含具体路径和修复建议。
3. 证据格式错误：错误包含 `actual_vs_expected` 和 `suggested_fix`。
4. 所有阻断性错误：至少携带 `suggested_fix`/`missing_items`/`actual_vs_expected` 之一。

### 11.2 授权文件模板

1. 从任务包生成模板：scope 字段自动填充。
2. 空任务包生成模板：包含格式说明和 hint。
3. 模板输出到文件：内容可被 `harness run --authorization` 直接消费。

### 11.3 跨平台任务

1. `.ps1` 文件在 macOS 上被识别为跨平台任务。
2. 跨平台任务验证分层：当前平台正常执行，目标平台标记 `pending_verification`。
3. 准入提示包含平台信息和补验建议。
4. 非跨平台任务不受影响。

### 11.4 外部完成任务补录

1. 非终态任务可被 `task adopt` 补录。
2. 补录后任务状态为 `complete`，`verification_status=adopted_external`。
3. 补录事件完整记录。
4. 补录后提示添加到质量账本。
5. 终态任务不可被补录。

## 13. 风险与控制

| 风险 | 控制 |
|---|---|
| 平台检测误判 | 仅基于文件后缀，不基于内容；误判时用户可通过 facts 覆盖 |
| 授权模板被滥用 | 模板只是起点，仍需显式提交和校验 |
| actionable 错误泄露敏感信息 | `suggested_fix` 只包含命令模板，不包含实际路径或凭证 |
| 补录机制被用于伪造完成 | 补录记录明确标记 `adopted_external`，不伪造验证证据 |

## 14. 完成定义

只有同时满足以下条件，才可以声明本方案完成：

1. 本文档的必需回归矩阵全部通过。
2. 当前源包 self-test 和 package 检查通过。
3. 临时项目完成 init/upgrade、跨平台任务、授权模板、错误提示、任务补录全链路测试。
4. ZBuddy 升级后验证 3 条账本记录对应的场景已改善。
5. 未提交、未推送、未安装或未验证的层级在完成报告中分别说明。
