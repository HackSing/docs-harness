# 2026-11-27 Docs Harness 2.38.1 发布验证

## 发布对象

- 版本：`2.38.1`（前版 tag：`v2.38.0`）
- 触发原因：同步升级大仓下游 `zbuddy-desktop`（77 个历史运行态证据包）时，发现 `2.38.0` 逐证据文件调用 `git check-ignore` 引发数千次子进程超时（>180s），且存在 1 个既有残缺历史证据包阻断 `assets-check --fast`。
- 前台/后台验证说明：全程在后台进程非交互执行聚焦单测、版本一致性检查、自检、打包与大仓实测，未弹出任何可见窗口、弹窗或抢夺焦点，前台持续时长 0 秒。

## 改动路径

- `scripts/runtime_packet.py`：新增 `git_ignored_set`（单次 `git check-ignore --stdin -z` 批量判定）。
- `scripts/runtime_check.py`（582 行，<=600）：移除逐证据文件 `_git_ignored` 调用，改为验证末尾调用一次 `_validate_git_ignores`。
- `scripts/asset_checks.py`：`check_cross_asset_relations(..., fast=fast)` 新增 `_changed_runtime_tasks` 与 `_packet_has_acceptance_ref`，`--fast` 仅校验改动中或带 `acceptance_ref` 的提交态证据包；全量检查巡检全部提交态证据包，未改动的存量无关联坏包报 `runtime.verification` WARN，改动中或带 `acceptance_ref`/`live_e2e` 的坏包仍硬 FAIL。
- `docs/contracts.md`、`docs/CODEMAP.md`、`tests/test_live_e2e_verification.py`：同步契约与存量包 `--fast`/全量回归用例。
- 版本与发布元数据：`scripts/harness.py`、`VERSION`、`package.json`、`SKILL.md`、`evals/evals.json`、`plan-templates/{levels,profiles}/*.json`、`README.md`、`CHANGELOG.md`、`AGENTS.md`、`.docs-harness/config.json`。

## 验证命令与退出码

- 验证层级：`focused_test`（L2）+ `local_runtime`（L3，真实大仓 `zbuddy-desktop` 77 包实测）+ `package_or_install`（L4）
- 聚焦测试：`python -X utf8 -m unittest tests.test_runtime_check tests.test_live_e2e_verification tests.test_assets_check tests.test_asset_checks_semantics tests.test_release_version_sync tests.test_agent_prompt_verification tests.test_cli_surface -v` → 退出码 0

- 门禁自检：`release sync --strict`、`self-test`、`assets-check --strict`、`npm pack --dry-run`、`report check`、`git diff --check` → 全部退出码 0

## 编码质量自查

1. **是否引入了重复逻辑及依据**：没有。`git_ignored_set` 统一替代了 `runtime_check.py` 内两处分散的 `_git_ignored` 调用；`asset_checks.py` 直接复用 `check_packet`。
2. **新增抽象各自的职责**：`runtime_packet.git_ignored_set` 负责批量 git 忽略查询；`asset_checks._changed_runtime_tasks` 与 `_packet_has_acceptance_ref` 负责 `--fast` 增量筛选与存量包分层判责。
