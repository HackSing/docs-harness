### Docs Harness
- 定义：为没有原生 Hook 的 AI 编程宿主提供可安装、可追踪、可验收，并且"主交付优先、文档异步治理"的任务控制闭环。版本 1.6.5，负责 Gate、任务包、上下文、授权、证据、后台 Job 和 Git 交付检查。
- 别名：docs-harness、harness

### Gate
- 定义：风险分类机制，由宿主通过 facts 提交 gate_assessment 声明，控制器强制安全底线（security-sensitive、destructive-data、release-external），未声明时回退关键词推断。用于控制任务的准入流程和重准入策略。
- 别名：风险门控、gate_assessment

### task-package/v2
- 定义：Docs Harness v1.6.5 的任务包格式，包含 task_intent、mutation_profile、read_scope、write_scope、git_scope、external_scope 等字段，定义任务的意图、变更面和范围约束。
- 别名：任务包v2、task_package_v2

### evidence-declaration/v1
- 定义：证据声明草案格式，宿主只需声明 type、write_set、conclusion 等核心字段，控制器代铸 task_id、covers、ttl、digest 等装订字段，生成完整的 evidence-receipt/v2 收据。
- 别名：证据声明、evidence_declaration

### verification_commands
- 定义：验证命令配置，允许在 plan 中声明可机器执行的验证命令（如 npm run verify），verify 阶段自动执行并通过 produces 字段映射到证据类型，实现 test_result 等收据的自动铸造。
- 别名：验证命令、verification_cmd

### background_job/v2
- 定义：后台治理任务格式，支持 knowledge_bootstrap、knowledge_incremental_sync、delivery_governance、critical_followup 四种类型，使用统一的 prepare、dispatched、running、progress 状态机管理复杂后台任务。
- 别名：后台Job、background_job

### write_scope_violation
- 定义：写入范围违规错误码，当 reported_writes 中存在不被 write_scope 覆盖的路径时触发，导致 full_readmission（exit 4）并进入重准入循环。
- 别名：范围违规、scope_violation

### new_risk_gate
- 定义：新增风险门控错误码，当 verify 发现新的 Gate（如 code-edit）而 run 阶段未声明时触发，需要重新准入并补充 Gate 声明。
- 别名：新风险门控、risk_gate

### plan_scope_mismatch
- 定义：计划范围不匹配错误码，当 plan 提交的 scope 与 package 的 allowed_scope 不一致时触发，要求重新准入。当前逻辑下即使 plan scope 是严格超集也不会自动重编译。
- 别名：范围不匹配、scope_mismatch

### unattributed_drift_overlap
- 定义：未归因漂移重叠错误码，当工作区存在无法证明来源的变更且与读写范围重叠时触发，控制器会尝试 auto-attribution 自动归因。
- 别名：漂移重叠、drift_overlap

### incrementally_recompile_new_gates
- 定义：增量重编译函数，针对仅新增普通 Gate 的情况进行原子追加准入，避免完整重新准入的高成本。但当前只在 blocker_codes == {"new_risk_gate"} 时触发，存在时序问题。
- 别名：增量重编译、incremental_recompile

### auto-attribution
- 定义：自动归因机制，当 write_scope 内存在未归因写入时，控制器自动生成 workspace_attribution 收据认领这些路径，减少人工补证据的开销。可通过 verification.auto_attribute_in_scope=false 关闭。
- 别名：自动归因、workspace_attribution

### git_sync_landed_scope
- 定义：Git 同步落地范围，记录 git_sync 过程中 pull 下来的已落盘文件路径，自动并入 write_scope 进行归因，避免远端漂移导致的误判。
- 别名：落地范围、landed_scope
