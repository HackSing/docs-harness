文档按版本边界分层组织：`docs/` 根目录存放当前产品真源（`contracts.md`、`architecture.md`、`testing.md`、`todo.md` 等），由 `docs/README.md` 作为文档地图统一索引；`docs/plans/` 仅保留当前生效的方案（如 v2.0.0 direct-first plan），并通过 `plans/README.md` 明确排除已被替代的历史方案；`docs/history/` 作为只读档案保存 1.x 的方案、审查记录和验证脚本，其 `history/README.md` 声明该目录不参与默认知识检索且不在 npm 发布包中；`docs/migrations/v2.0.0.md` 是唯一的升级入口文档，以 CLI 命令序列（`project upgrade --json` → `--apply` → `project diff/check`）定义预览-应用-验收三段式流程，并严格规定受管旧工件清理、项目内容保留、失败关闭条件与回滚边界。依赖方向单向：当前文档引用自身和源码实现，历史文档不反向影响当前行为。
