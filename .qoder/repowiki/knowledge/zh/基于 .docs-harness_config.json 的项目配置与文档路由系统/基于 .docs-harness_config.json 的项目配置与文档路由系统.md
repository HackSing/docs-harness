## 1. 采用的方案

该仓库是一个 Python CLI（`scripts/harness.py`），通过 npm 包形式分发。配置系统完全由 Python 代码实现，没有引入第三方配置框架：
- 项目级配置以 JSON 文件形式存放在目标工作区的 `.docs-harness/config.json`。
- 配置读取、校验、合并与回退逻辑全部内联在 `scripts/harness.py` 中。
- 不存在 `.env`、`.yaml`、`.toml`、`application.properties` 等其它格式；也没有环境变量注入机制。
- 版本信息通过根目录的 `VERSION` 文件与 `package.json` 中的 `version` 字段共同维护，CLI 命令通过 `self-test` 脚本暴露。

## 2. 关键文件

- `scripts/harness.py`：唯一承载配置加载与校验逻辑的文件。核心函数包括：
  - `project_config(target)`：从 `<target>/.docs-harness/config.json` 读取并返回 dict，缺失时返回 `None`。
  - `document_route_config(target)`：解析 `config.json` 中的 `background_governance.document_routes`，对每个路由进行白名单、长度、字符集、路径安全（禁止 `..`、绝对路径、符号链接、指向 `.git`/`.docs-harness`）校验，非法则直接报错而非回退。
  - `resolve_document_routes(target, required_kinds)`：先尝试显式配置，再按 `DOCUMENT_ROUTE_FILE_KINDS` 自动探测候选（如 `architecture.md`、`changelog`、`todo`、`adr`、`reviews`），若候选不唯一或缺失则报告错误。
  - `governance_required_kinds(deliverables)`：根据交付物清单推导所需的文档类别集合。
  - `configured_volatile_verification_patterns(target)`：从 `verification.volatile_paths` 读取验证模式，要求为非空字符串数组。
  - `verification.command_cache_enabled` / `verification.auto_attribute_in_scope` 等布尔开关也在此处校验。
- `package.json`：声明 npm 包名 `docs-harness`、版本 `1.7.2`，并通过 `files` 字段限定发布产物包含 `scripts/harness.py`、`VERSION`、`docs/`、`harness-home/`、`evals/`、`tests/`。
- `VERSION`：存放当前版本号，供 CLI 与发布流程使用。
- `tests/test_harness.py`：单元测试覆盖部分配置解析行为。

## 3. 架构与约定

- **单一真源**：所有运行时配置都来自被操作的目标工作区下的 `.docs-harness/config.json`，工具本身不维护全局状态或默认配置表（除内置的 `DOCUMENT_ROUTE_KINDS`、`DOCUMENT_ROUTE_FILE_KINDS`、`GOVERNANCE_DELIVERABLE_ROUTES` 常量外）。
- **严格校验优先于回退**：当 `config.json` 存在但结构非法时，`document_route_config` 会返回错误列表而不是静默忽略；`resolve_document_routes` 将结果标记为 `invalid_config` 或 `unresolved`，并附带 `reason_code` 与 `errors`。
- **显式配置优先于自动发现**：文档路由的解析顺序是：先读 `background_governance.document_routes` 中的显式映射，再按固定规则在 `<target>/docs` 及 `<target>` 下扫描候选文件/目录；只有当显式配置缺失时才走自动发现。
- **安全约束**：路由路径必须相对、不能以 `/` 开头、不能包含 `*?[]`、不能有控制字符、不能指向 `.git` 或 `.docs-harness`、不能是符号链接，且最终路径必须在目标工作区内（通过 `resolve().relative_to()` 校验）。
- **可复现契约**：`resolve_document_routes` 会为最终路由合同计算 SHA-256 fingerprint（`document_route_fingerprint`），用于后续一致性检查。

## 4. 约定与约束

- 配置文件位置固定为 `<target>/.docs-harness/config.json`，不存在其他位置或别名。
- 配置必须是 JSON 对象；非 dict 会被丢弃并视为无配置。
- `background_governance.document_routes` 的键必须是预定义的 `DOCUMENT_ROUTE_KINDS` 之一（如 `architecture`、`changelog`、`todo`、`adr_root`、`reviews_root`），未知键会作为错误上报。
- 文件类路由值长度限制为 ≤ 512 字符，且必须是存在的文件或目录（类型需匹配）。
- `verification` 子段必须是对象；其 `volatile_paths` 必须是非空字符串数组，`command_cache_enabled` 和 `auto_attribute_in_scope` 必须是布尔值。
- 所有配置错误统一通过 `HarnessError` 抛出，并附带 `code="invalid_project_config"` 或 `code="invalid_document_route_config"` 等结构化错误码，便于调用方区分失败原因。
- 该仓库自身不包含示例 `config.json`；实际使用方需在各自项目中创建 `.docs-harness/config.json` 来启用 Docs Harness 功能。
